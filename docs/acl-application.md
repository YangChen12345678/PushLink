# ohos.permission.SUBSCRIBE_NOTIFICATION 权限申请说明

> 用于受限权限申请表单的「申请理由」字段。
> 表单有字数限制时使用文末的精简版。

## 完整版

### 一、应用功能与使用场景

PushLink 是一款面向双持用户的通知同步工具，服务于同时使用 HarmonyOS 手机与 iPhone 的个人。
用户开启后，可将自己指定的应用通知同步显示到本人的 iPhone 上。

典型使用场景：HarmonyOS 手机正在充电、放在背包中或不在身边时，用户通过随身携带的 iPhone
及时获知本机通知，避免错过重要信息。这与用户通过手表查看手机通知属于同一类需求——
区别仅在于承载显示的设备是用户的另一台手机，而非腕上设备。

### 二、为何需要本权限

实现通知同步，必须能够读取本机通知中心的内容。HarmonyOS 提供的
`NotificationSubscriberExtensionAbility` 是达成该目的的唯一能力，不存在可替代的公开接口。
若无此权限，应用的核心功能无法成立。

### 三、权限的使用方式

- 通过 `NotificationSubscriberExtensionAbility` 订阅本机通知，仅在扩展回调中读取
  通知的标题、正文、来源包名与时间戳，不获取其他信息。
- **转发范围完全由用户在系统授权界面决定**。应用调用系统提供的授权页面，
  由用户逐个勾选允许读取的应用，应用内不另设开关、不维护第二份名单。
- 过滤策略为**默认拒绝**：未出现在系统授权列表中的来源、名单读取失败、名单为空，
  一律丢弃且不发送。应用不存在任何形式的默认放行。
- 支持按应用分身粒度区分（包名 + appIndex），确保对某一实例的授权不会误放行另一实例。

### 四、用户数据保护措施

以下均为已实现的技术措施，可在应用中验证：

**1. 内容端到端加密，中转服务无法解密**

通知内容在离开设备前即以 AES-256-GCM 加密。加密密钥由用户在 HarmonyOS 手机与 iPhone
两端各自手动配置，**不上传、不托管、不经过任何服务器**。中转服务全程只能接触密文，
传输路径上的任何一方都无法还原通知内容。

加密实现已通过 NIST SP 800-38D 标准测试向量逐字节比对验证。每条消息使用密码学安全
随机数生成独立初始化向量。

**2. 不留存通知内容**

通知成功投递后立即从本地队列删除，不保存任何已发送通知的历史记录。

**3. 诊断信息脱敏**

本地诊断记录仅包含事件标识、来源包名、投递结果、耗时与错误码，
**不含通知标题、正文、密文或任何密钥**。

**4. 数据不离开设备**

已移除应用的备份扩展能力，用户配置与待发队列不会随系统备份离开本机。
本地数据库整库加密，密钥由系统安全环境托管并绑定本设备与本应用。

**5. 日志无明文**

全部日志仅输出内容长度与掩码值，不输出通知标题、正文或任何密钥。
该约束由统一日志出口强制执行，并有自动化测试覆盖。

### 五、通知的接收者始终是用户本人

本应用的同步目标是用户自己的另一台设备，不涉及向任何第三方披露通知内容，
也不存在数据收集、分析或商业化利用。应用不收费、无广告、不含任何统计或追踪组件。

应用包含 27 项自动化测试用例并全部通过，覆盖加密正确性、白名单默认拒绝、
内容截断与事件标识稳定性等关键路径，如有需要可提供完整测试报告。
